# بناء إضافات مكتبة

> **الحالة: المرحلة 1 في `main`.** البيان وحزمة `.mkplugin`، ومضيف الإضافات مع عزل نظام التشغيل،
> والواجهة البرمجية للإضافات مع مقابض الوسائط، ومراحل الإضافات في الطابور، والتثبيت من ملف،
> والمنح، ودورة الحياة، والصحة وقاطع الدائرة، والإعدادات، وصفحة الإضافات للمسؤول، وأداة `mkp`
> مع بيئة الاختبار (للغة Rust). تعمل الإضافات على جهاز رئيسي يستخدم Postgres، في macOS ولينكس
> (لا في ويندوز بعد). والمرحلة 2 قيد البناء: التوقيع في `main`. أما المرحلة 3 فمُخطَّط لها.
> و[مرجع الإضافات](reference.ar.md) يُولَّد من الشيفرة عند بناء هذا الموقع، فيطابق `main` دائمًا.

## ما الإضافة

تضيف الإضافة وظيفة إلى منزل مكتبة دون تغيير شيفرة مكتبة نفسها. فهي:

- **تأخذ المهام من طابور المهام.** تعلن إضافتك عن مراحل. تضع مكتبة مهمة لمرحلة ما في الطابور
  عند وقوع حدث ثابت (أُضيف فيديو، أو جهز نص مفرّغ)، أو وفق جدول زمني، أو حين تطلبها مرحلة
  أخرى من مراحلك.
- **لا تصل إلى الإنترنت.** لا تستطيع فتح مقبس (socket)، ولا حلّ اسم نطاق، ولا إرسال طلب HTTP.
  ولا ترى القرص. ويُفرض هذا مرتين: بيئة تشغيل WebAssembly لا تربط أي واجهات للشبكة أو لنظام
  الملفات، والعملية التي تشغّل الإضافات يقيّدها نظام التشغيل.
- **لا تنال من الواجهة البرمجية إلا ما يمنحه المشرف.** تعلن عن قدرات مثل `library.read` أو
  `chapters.write`. يمنحها المشرف عند التثبيت، ويختار المكتبات التي تراها الإضافة، وتتحقق
  الواجهة البرمجية من الأمرين في كل استدعاء.

تكتب الإضافة نتائجها عبر الواجهة البرمجية: حقول البيانات الوصفية، والوسوم، والفصول، والترجمات
المصاحبة، والصور الفنية، واقتراحات يراجعها المشرف، وبياناتها الخاصة. ويمكنها أن تعلن عن نموذج
إعدادات، ولاحقًا عن لوحات للقراءة فقط ترسمها التطبيقات.

الإضافة حزمة واحدة موقّعة (`.mkplugin`) تضم مكوّن WebAssembly، والبيان، ونصوصًا بالإنجليزية
والعربية، وأيقونة، وواجهة اختيارية معرَّفة على هيئة بيانات. يمكنك كتابتها بلغة Rust، أو
TypeScript أو JavaScript، أو Python، أو Go (TinyGo).

## ما لا تستطيع الإضافة فعله

- الوصول إلى الإنترنت، بأي إذن كان. لا توجد قدرة باسم `network`.
- تغيير التشغيل أو البث، أو إضافة مسارات للواجهة البرمجية تخدم التطبيقات.
- تشغيل شيفرة داخل التطبيقات. نماذج الإعدادات واللوحات بيانات، ومكتبة هي التي ترسمها.
- العمل عند الإقلاع أو خارج مهمة.
- قراءة المستخدمين، أو الجلسات، أو الرموز (tokens)، أو الأسرار، أو مسارات الملفات، أو عناوين
  الأجهزة.
- التواصل مع إضافة أخرى، إلا بقراءة بيانات اختارت تلك الإضافة تصديرها، وبمنح صريح.

## الخطط والمراحل

يُطلق التصميم على مراحل. يحدد كل دليل المرحلة التي تنتمي إليها كل ميزة.

| المرحلة | المحتوى | الحالة |
|---|---|---|
| 1 | البيان والحزمة، ومضيف الإضافات والعزل، والواجهة البرمجية للإضافات ومقابض الوسائط، ومراحل الطابور | في `main` |
| 1 | دورة الحياة، والمنح والأدوار، والصحة، والتثبيت من ملف، والإعدادات، وصفحة الإضافات، وحزمة التطوير وأداة الاختبار | في `main` (حزمة التطوير للغة Rust فقط) |
| 2 | التوقيع والثقة | في `main` ([التوقيع وسلسلة الثقة](trust.ar.md)) |
| 2 | متجر مكتبة، والفحوص الآلية والمراجعة، والفهرس، والتحديثات، ومفتاح الإيقاف الطارئ | قيد البناء |
| 3 | الإضافات المدفوعة، واللوحات في كل التطبيقات، والحوسبة المحلية (التضمينات والنموذج اللغوي للجهاز الرئيسي) | الحوسبة المحلية في `main` (الإصدار القادم)؛ والباقي مُخطَّط |

ومن المخطط أيضًا أن تنتقل مراحل الطابور الخاصة بمكتبة نفسها لتعمل خلف البيان نفسه والتوزيع نفسه
والواجهة البرمجية نفسها، بوصفها إضافات من الطرف الأول. ولا يغيّر هذا العمل ما تستطيع إضافات
الأطراف الثالثة فعله.

## ما الموجود اليوم

في الفرع `main` تستطيع كتابة إضافة بلغة Rust بأداة `mkp`، واختبارها في بيئة الاختبار، وتحزيمها،
ويستطيع المسؤول تثبيتها من ملف في الإعدادات، الإضافات. ولا يشغّل المشرف على العمليات المضيف
`maktaba-plugind` إلا ما دامت إضافة مشغّلة؛ ويشغّل خط المعالجة كل مهمة في بيئة عزل جديدة، وتجيبها
الواجهة البرمجية للإضافات عبر مقبس يونكس. انظر [تثبيت الإضافات وإدارتها](installing.ar.md) لما
يفعله المسؤول.

ومن جهة أخرى يستطيع خط معالجة مكتبة تحميل حزم Python المسجّلة ضمن مجموعة نقاط الدخول `maktaba.extensions`.
هذه ميزة للمطوّرين مخصّصة لتكاملات مكتبة نفسها: تعمل هذه الحزمة داخل عامل خط المعالجة بصلاحيات
كاملة. وهي ليست نظام الإضافات، وليست مخصّصة لشيفرة من أشخاص آخرين.

## الإضافة في صورة واحدة

```
queue job (pool "plugins")
  -> pipeline worker asks the API for a per-job token
  -> plugin host runs your component's run(stage) in a fresh sandbox
       your code calls maktaba:plugin/* imports
       the host forwards each call with the token to the plugin API
       the API checks token, capability, library scope and quota
  -> result goes back to the queue (retry, park or done)
```
