# التدفّقات: كيف ترتبط الإضافات بالطابور

> **الحالة:** صيغة التدفّق وحقول الرسم في البيان وفحص التدفّق **في `main`**: يفحص الجهاز
> الرئيسي كل تثبيت وتشغيل وتحديث وتراجع، ويستخدم التحقّق في المتجر الفحص نفسه. وإطلاق الأحداث
> (الواجهة البرمجية للإضافات 1.1) وسلالة المهام وقت التشغيل والمخطط المرسوم والإضافات على
> الأجهزة المنضمّة **في `main`** كذلك. والحقول والرموز بدقة في [مرجع الإضافات](reference.ar.md).

لا ترتبط الإضافة بالطابور إلا عبر الرسم البياني الذي تعلنه. ولا طريق غيره: لا يُنشأ أبدًا
رابط أو طلب أو حدث خارج الرسم المُعلَن، وترفض كلٌّ من الواجهة البرمجية للإضافات ومحمِّل
الجهاز الرئيسي وخط المعالجة أيَّ شيء منها.

## التدفّق

يصف **التدفّق** مجموعة من الإضافات تعمل معًا: مراحل كل إضافة، والأحداث الأساسية التي ترتبط بها
كلٌّ منها، والأحداث التي تنشرها، ومن يشترك في ماذا. وهو الملف `flow.toml` في جذر كل حزمة من
المجموعة، بالبايتات نفسها في كلٍّ منها، موقَّعًا مع الحزمة. والإضافة الواحدة تدفّقٌ من عضو واحد.

```toml
schema  = 1
id      = "dev.example.chapters"
version = "1.2.0"

[strings]
name    = "flow.name"

[[plugin]]
id      = "dev.example.silences"
version = ">=1.4.0, <2.0.0"

  [[plugin.stage]]
  name     = "find_silences"
  subject  = "video"
  triggers = ["audio.ready"]
  emits    = ["silences.found"]

  [[plugin.event]]
  name    = "silences.found"
  subject = "video"
  payload = "events/silences.found.schema.json"

[[plugin]]
id      = "dev.example.chapter-writer"
version = ">=1.0.0, <2.0.0"

  [[plugin.stage]]
  name        = "write_chapters"
  subject     = "video"
  triggers    = ["plugin:dev.example.silences/silences.found"]
  may_request = ["tidy"]

  [[plugin.stage]]
  name     = "tidy"
  subject  = "video"
  triggers = ["stage:write_chapters"]
```

وهذا التدفّق مرسومًا (وترسم مكتبة المخطط نفسه على شاشة التثبيت وصفحة الإضافات، من الشيفرة نفسها):

![مثال تدفّق من إضافتين: الصوت جاهز، ثم تُطلق silences/find_silences الحدث silences.found، فيشغّل chapter-writer/write_chapters، ثم chapter-writer/tidy](example.svg)

```
audio.ready ──► silences/find_silences ──► ◆ silences.found ──► chapter-writer/write_chapters ──► chapter-writer/tidy
```

وللمُشغِّل إحدى ثلاث صيغ:

| الصيغة | المعنى |
|---|---|
| `audio.ready` | بعد حدث أساسي ثابت ([القائمة](queue-and-api.ar.md)) |
| `stage:<name>` | بعد مرحلة أخرى من الإضافة نفسها، حين تتغيّر مخرجاتها |
| `plugin:<id>/<event>` | حين تنشر الإضافة `<id>` الحدث `<event>` |

## نصيب البيان

يحمل كل بيان نصيبه من التدفّق، ويجب أن يطابقه تمامًا: المراحل نفسها وموضوعاتها، والمُشغِّلات
والأحداث المُطلَقة والطلبات، والأحداث المنشورة نفسها، ومدخلًا في `[[depends]]` لكل إضافة يشترك
في أحداثها.

```toml
[[stage]]
name    = "find_silences"
subject = "video"
export  = "run-find-silences"
version = 3
emits   = ["silences.found"]
  [[stage.trigger]]
  event = "audio.ready"

[[event]]
name    = "silences.found"
subject = "video"
payload = "events/silences.found.schema.json"   # a JSON Schema in your package
```

ومن جهة المشترك:

```toml
[[stage]]
name    = "write_chapters"
subject = "video"
export  = "run-write-chapters"
version = 1
  [[stage.trigger]]
  event = "plugin:dev.example.silences/silences.found"
  [[stage.trigger]]
  stage = "find_more"                           # or after one of its own stages

[[depends]]
plugin  = "dev.example.silences"
version = ">=1.4.0, <2.0.0"
```

ويطلب المشترك أيضًا الصلاحية `events.subscribe:<publisher id>`، ويوافق عليها المسؤول كأي صلاحية
أخرى.

## القواعد

1. **أوراقٌ بعد الأساس.** لا تعمل مراحلك إلا بعد الأحداث الأساسية. ولا يصل شيء مما تفعله مراحلك
   إلى مرحلة أساسية: لا طلب ولا مُشغِّل ولا حدث يسمّي واحدة منها، ولا تنتظر مرحلة أساسية مخرجاتك.
2. **الإضافات الأخرى عبر الأحداث المنشورة وحدها.** لا تسمّي أبدًا مرحلة إضافة أخرى؛ بل تشترك
   في حدث تنشره. وتُفحص الحمولة بمخطط الناشر حين يُطلَق الحدث.
3. **بلا حلقات.** لا حلقة في الرسم المجمَّع للجهاز الرئيسي (الأحداث الأساسية، ومراحل كل إضافة
   مفعَّلة وأحداثها). ويسمّي الرفض الحلقة، مثلًا:
   `dev.example.alpha/tag → plugin:dev.example.alpha/a.tagged → dev.example.beta/check →
   plugin:dev.example.beta/b.checked → dev.example.alpha/tag`.
4. **16 خطوة على الأكثر.** لا تطول سلسلة مراحل مُعلَنة من حدث أساسي عن 16، وهو حدّ القفزات وقت
   التشغيل.
5. **كل شيء موجود.** كل حدث مسمّى إمّا حدث أساسي وإمّا تنشره إضافة من التدفّق أو إضافة يعتمد
   عليها، بإصدار يقبله، وعن النوع نفسه من الموضوعات.

**أين يُفحص.** يُجري التحقّق في المتجر الفحص على التدفّق المرفوع والإضافات التي يعتمد عليها،
ويرفض التدفّق الذي يخالف قاعدة، مسمّيًا الحلقة أو الرابط الخاطئ. ويُجري الجهاز الرئيسي الفحص
نفسه مرة أخرى عند التثبيت والتشغيل والتحديث والتراجع، على كل إضافة مفعَّلة: فقد يجمع جهاز رئيسي
تدفّقات لم يرها المتجر معًا قط، والتثبيت من ملف لا يمرّ بالمتجر. والإضافة التي تغيب الإضافة التي
تسبقها تُثبَّت مع ذلك؛ وتبقى مراحلها المشتركة خاملة، وتذكر صفحتها أيّ إضافة غائبة.

## إطلاق حدث

تُطلق المرحلة حدثًا تعلنه في `emits`، عن موضوع داخل نطاق مهمتها، بحمولة كائن JSON (16 ك.ب على
الأكثر) يقبلها مخطط الحدث:

```rust
events::emit("silences.found", &job::job_subject(), r#"{"silences": 4}"#)?;
```

والمخطط صيغة صغيرة من JSON Schema: للكائن `properties` و`required` و`additionalProperties`،
ولكل قيمة `type` و`enum` و`minimum` و`maximum` و`maxLength` و`items` و`maxItems`. والحمولة التي
يرفضها تُجاب بـ`invalid` ولا يُرسل شيء. ويذهب الحدث إلى كل مرحلة مشتركة وافق عليها المسؤول، وحين
تنتهي مهمتك بنجاح فقط: المهمة التي تفشل لا ترسل شيئًا. ويقرؤه المشترك بـ`job::payload()`:

```json
{"event": "silences.found", "from": "dev.example.silences", "payload": {"silences": 4}}
```

وتتقاسم الطلبات والأحداث ميزانية واحدة من 1,000 لكل مهمة. ويحتاج الإطلاق إلى الواجهة البرمجية
للإضافات 1.1: أعلن `plugin_api = "1.1"`؛ وتبقى إضافة 1.0 تعمل دون تغيير.

## الحلقات وقت التشغيل

يرفض فحص التدفّق كل حلقة يُظهرها الرسم المُعلَن، لكن الحلقة قد تمرّ أيضًا عبر البيانات: تكتب إضافتك
وسمًا، فتعيد مكتبة خطوة لأن مدخلاتها تغيّرت، ويشغّل الحدث الأساسي الذي تطلقه تلك الخطوة إضافتك مرة
أخرى على الفيديو نفسه. لذلك تحمل كل مهمة إضافة **سلالتها**: من أين بدأت سلسلتها، وكم مهمة إضافة
مرّت بها، وأيّ أزواج (مرحلة، موضوع). وترفض مكتبة الطلب أو الحدث الذي يجعل السلسلة أطول من **16**
مهمة إضافة، أو يعيد تشغيل مرحلة على موضوع سبق أن عملت عليه في السلسلة نفسها؛ وتترك الكتابة سلالة
كاتبها على الفيديو **10 دقائق**، فترثها المهمة التي يبدؤها حدث أساسي هناك. ويُجاب الاستدعاء بـ`scope`،
ولا يُضاف شيء إلى الطابور، وتفشل المهمة بالسبب **`plugin_loop`**: لا يُعاد تجريبها، والتغيير الحقيقي
التالي على العنصر يشغّل مرحلتك مرة أخرى. والسلالة ملك مكتبة: لا تُظهرها حمولة مهمتك أبدًا، وتُرفض
حمولتك التي تسمّي `_lineage`.

## أين تعمل الإضافة

قد تكون للجهاز الرئيسي أجهزة منضمّة (حاسوب فيه معالج رسوميات، أو جهاز تخزين شبكي). ويقول البيان أين
يجوز أن تعمل إضافتك:

```toml
placement = "any"   # "home" (the default), "any", or "gpu"
```

| المكان | تعمل على |
|---|---|
| `home` (أو لا شيء) | الجهاز الرئيسي وحده |
| `any` | الجهاز الرئيسي وكل جهاز منضمّ؛ ويأخذ كلٌّ منها مراحلك من الطابور كما يأخذ العمل الأساسي |
| `gpu` | الأجهزة التي فيها معالج رسوميات (جهاز Mac بشريحة Apple، أو جهاز فيه معالج NVIDIA)؛ وتأخذ مراحلك مجمّع `gpu` |

ولا يتغيّر شيء آخر في شيفرتك. يثبّت الجهاز الرئيسي الإضافة ويوافق عليها؛ ويجلب كل جهاز يجوز له
تشغيلها الحزمة من الجهاز الرئيسي ويتحقّق منها (البصمة التي سجّلها الجهاز الرئيسي، والتواقيع التي
ثبّتها بها، وكل ملف) قبل أن يضعها، ثم يشغّلها في مضيفه المعزول. والقراءات والوسائط يخدمها الجهاز نفسه؛ وكل
كتابة (الوسوم والحقول والفصول والترجمات والصور وبياناتك والاقتراحات والتنبيهات والطلبات والأحداث،
وما تطلبه من نماذج الجهاز الرئيسي) يطبّقها الجهاز الرئيسي، بفحوص الصلاحيات والحصص والسلالة نفسها، فتتصرّف الإضافة كما هي أينما عملت.
وتظهر سجلاتك وصحتها في صفحة الإضافات على الجهاز الرئيسي. وإيقاف الإضافة على الجهاز الرئيسي يصل إلى
كل جهاز عند استدعائه التالي.

## الرموز

| الرمز | متى |
|---|---|
| `flow_cycle` | التغيير سيُغلق حلقة؛ ويُسمّى المسار |
| `flow_core_edge` | مرحلة تصل إلى مرحلة أساسية |
| `flow_foreign_stage` | مرحلة تسمّي مرحلة إضافة أخرى |
| `flow_foreign_event` | مرحلة تُطلق حدثًا لا تنشره إضافتها |
| `flow_unknown_event` | مُشغِّل يسمّي حدثًا لا ينشره أحد |
| `flow_subject_mismatch` | حدث عن نوع موضوع غير الذي تعمل عليه المرحلة |
| `flow_missing_plugin` | إضافة سابقة غائبة أو خارج المدى (تحذير على الجهاز الرئيسي) |
| `flow_too_deep` | سلسلة أطول من 16 مرحلة |
| `flow_manifest_mismatch` | البيان يختلف عن مدخله في التدفّق |
| `flow_not_member` | الإضافة ليست في تدفّقها بهذا الإصدار |
| `plugin_loop` | وقت التشغيل: طلب أو حدث سيُحدث حلقة (سبب فشل) |

وعلى الجهاز الرئيسي يكون الرفض `409 plugin_flow_cycle` (لحلقة) أو `409 plugin_flow_invalid`،
مع كل نتيجة بالإنجليزية والعربية.
