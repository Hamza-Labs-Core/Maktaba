Troubleshooting on a NAS

Each message Maktaba shows, what it means, and the fix.

All NAS guides · العربية

Messages printed before the web app is up appear in the container's log (Container Manager's Log tab, TrueNAS's app logs, Unraid's Docker log), in English and then in Arabic.

Maktaba cannot write to its data folder

The container stopped right after it started, and its log says it cannot write to its data folder as user 1026 (or 568, or 99). The folder you mounted for Maktaba's data belongs to another user. Give that user Read/Write on the folder (the log names the NAS's own screen for it), then start the container again. Maktaba never changes permissions itself.

Maktaba does not run as root

Set the container's user to an ordinary user (user: in the compose file, such as 1026:100), and remove privileged and any Docker socket mount.

A port is taken

Maktaba uses 8088 (the web app), 8080 (the apps and the home's other machines), 8081 (live TV) and 54329 (the database). What you see depends on how the port was chosen:

  • A default port moved: setup or Settings → This machine says that port 8080 (or 8088, or 8081) is used by another program, so Maktaba uses 8780 (or another port up to 8790) instead. Nothing to fix: the new port is kept, and apps and machines find it. Use the address setup shows; your NAS's Web UI button may still open 8088.
  • A port you set stopped Maktaba: the container's log says the port is used by another program and names the setting, such as MAKTABA_WEB_PORT. A port you set is never moved. Set that variable to a free port, or stop the other program, then start the container again.
  • The database port: when another program holds 54329, the log names MAKTABA_POSTGRES_PORT. It is never moved: set the variable to a free port.
  • On a bridge network the container does not start, and Docker says port is already allocated: change the port on the NAS's side of the mapping (the left side of "8088:8088"), and set MAKTABA_PUBLIC_WEB_PORT (or _API_PORT, _STREAM_PORT) to the same number.

Where each NAS sets these variables: the compose file's [ports] block (Synology, QNAP, UGREEN, ASUSTOR, Docker), Additional Environment Variables (TrueNAS), and Show more settings in the template (Unraid). Change the firewall rule to the new port too.

A library shows No access

The user Maktaba runs as cannot read that folder: the share's permissions leave it out, the folder is not mounted in the container, or the disks are stopped (Unraid's array). Nothing in the library is treated as deleted. Give the user read access as the library page says, check the mount, then press Check access. Read only instead means Maktaba reads but may not write: fine, unless you want subtitles and converted copies beside your videos.

The render device can't be opened

Settings → This machine says the render device is there but the user can't open it: add the device's group to the container (group_add with the number stat -c %g /dev/dri/renderD128 prints). No render device is available means /dev/dri is not passed to the container at all. Either way Maktaba converts video in software until it is fixed.

Plugins are held

Many NAS kernels lack the file sandbox Maktaba gives plugins elsewhere, so plugins run inside the container's limits only. Maktaba's own plugins run; plugins from other developers wait for your yes. Settings → Plugins → Allow plugins with container-only isolation on this home, only if you trust them.

Not enough memory

Setup refuses when Maktaba may use less than 3.5 GB (a "4 GB" NAS just fits; a 2 GB one does not). Add memory if the NAS takes it, or raise the container's memory limit. Otherwise the NAS serves best as storage: run the Maktaba home on another computer, and it reads your media from the NAS.

An update did not go through

Manage → Updates says the new release is blocked: it was rolled back on the home, and the release you had runs again. The library stopped for a moment while the update changed its database. To let those changes finish, Maktaba ends the database sessions they wait on, a joined computer's copy of the database included; that copy makes itself again by itself. When the changes still fail, Maktaba goes back the quickest safe way, and the start screen and the container's log say which:

  • Nothing had to be put back: what the update changed so far only adds to the database, and the release you had runs on it as it is. Seconds.
  • Its changes were undone by its own Down scripts: the database is as the release you had knows it. Seconds to a few minutes.
  • Restored from the backup: anything else. The backup taken before the update goes back, which takes longer the larger the library: hours for tens of gigabytes.

You need do nothing. Your libraries, watch history and settings are as they were before the update, and the next release is installed in its update window when it comes out. Try it again on the Updates page tries the same release once more. Don't delete the data folder or its backups while it works.

An update waits for free space

Manage → Updates says Not enough free space on the data folder for a safe update, with what it needs and what is free: about 1 GB for the new release and a little more than the database's size for the backup taken first. Nothing is changed until there is room. Free space on the data folder's volume (old snapshots, other apps' files), and the update goes on in the next window.

A Light NAS asked to join another home

Joining a home on another computer as one of its machines says A Light NAS should be the Maktaba home or just storage: a NAS on the Light tier would slow down without helping that home much. Make the NAS the home instead, or keep it as storage, the home on the other computer reading your media from its shares. The join goes on only when you choose it explicitly.

The data folder is refused

Maktaba's database must be on a local disk: setup refuses a network share, and on Unraid the array's /mnt/user. Choose a folder on an SSD or a pool, such as /mnt/cache/appdata/maktaba. On spinning disks Maktaba works, a little slower.

Setup stops while getting Maktaba ready

Setup says Installing the tools failed or Downloading the models failed: the NAS could not reach the internet. Setup downloads the transcription and search tools (about 2 GB) and the speech models once. Check the NAS's network and its DNS, then run the setup command again: it goes on from where it stopped.

The library is empty after setup

The folders you gave setup only fill the folder list: add each library in Manage → Manage libraries → Add library. On a Light or Standard NAS its first scan then waits for the quiet hours (01:00 to 06:00 by default): Run now on the library's page starts it at once.
