Troubleshooting on a NAS

Each message Maktaba shows, what it means, and the fix.

All NAS guides · العربية

Messages printed before the web app is up appear in the container's log (Container Manager's Log tab, TrueNAS's app logs, Unraid's Docker log), in English and then in Arabic.

Maktaba cannot write to its data folder

The container stopped right after it started, and its log says it cannot write to its data folder as user 1026 (or 568, or 99). The folder you mounted for Maktaba's data belongs to another user. Give that user Read/Write on the folder (the log names the NAS's own screen for it), then start the container again. Maktaba never changes permissions itself.

Maktaba does not run as root

Set the container's user to an ordinary user (user: in the compose file, such as 1026:100), and remove privileged and any Docker socket mount.

A port is taken

Setup says that port 8080 (or 8088) is used by another program, so Maktaba uses 8780 (or another port up to 8790) instead. Nothing to fix: the new port is kept, and apps and machines find it. Use the address setup shows. If you would rather keep the old port, stop the program that holds it and restart Maktaba.

A library shows No access

The user Maktaba runs as cannot read that folder: the share's permissions leave it out, the folder is not mounted in the container, or the disks are stopped (Unraid's array). Nothing in the library is treated as deleted. Give the user read access as the library page says, check the mount, then press Check access. Read only instead means Maktaba reads but may not write: fine, unless you want subtitles and converted copies beside your videos.

The render device can't be opened

Settings → This machine says the render device is there but the user can't open it: add the device's group to the container (group_add with the number stat -c %g /dev/dri/renderD128 prints). No render device is available means /dev/dri is not passed to the container at all. Either way Maktaba converts video in software until it is fixed.

Plugins are held

Many NAS kernels lack the file sandbox Maktaba gives plugins elsewhere, so plugins run inside the container's limits only. Maktaba's own plugins run; plugins from other developers wait for your yes. Settings → Plugins → Allow plugins with container-only isolation on this home, only if you trust them.

Not enough memory

Setup refuses when Maktaba may use less than 3.5 GB (a "4 GB" NAS just fits; a 2 GB one does not). Add memory if the NAS takes it, or raise the container's memory limit. Otherwise the NAS serves best as storage: run the Maktaba home on another computer, and it reads your media from the NAS.

The data folder is refused

Maktaba's database must be on a local disk: setup refuses a network share, and on Unraid the array's /mnt/user. Choose a folder on an SSD or a pool, such as /mnt/cache/appdata/maktaba. On spinning disks Maktaba works, a little slower.
