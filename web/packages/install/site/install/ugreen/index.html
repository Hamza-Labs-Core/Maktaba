Install Maktaba on UGREEN

UGOS Pro's Docker app runs Maktaba from one compose file.

All NAS guides · العربية

Not yet tested on a UGREEN device. UGOS Pro's menu names below come from UGREEN's own guides, and the same file runs on every Docker host; tell us at GitHub what you find.

For UGOS Pro (the DXP models) with its Docker app. About 20 minutes. Maktaba runs as a user you make for it, never as root.

Before you start

  • Memory: Maktaba needs 3.5 GB it may use; the DXP models ship with 8 GB, a Standard tier (which tier).
  • An SSD for the data folder if there is one: the database and thumbnails are much faster there. Your media can stay on hard disks.
  • A GPU: the Intel models (N100, Pentium, Core) convert video with Quick Sync through /dev/dri.
  • SSH: Control Panel → Terminal → turn SSH on. Sign in with an administrator account; sudo -i gives a root shell.

1. Make a user and read its numbers

Control Panel → User Management → User → Add: name maktaba, a strong password, the role Standard User. Then, over SSH, run id maktaba: uid=1001 gid=100 is the answer 1001:100.

2. Give it its folders

  • Data: installing the Docker app makes a shared folder named docker. Make the folder maktaba inside it, such as /volume1/docker/maktaba (on an SSD volume when there is one), and give maktaba Read/Write on it.
  • Media: in Files → Shared Folder, open the properties of each folder with videos and give maktaba Read/Write where Maktaba may save subtitles and conversions, Read Only elsewhere.

Mount each folder in the container at its own path on the NAS, such as /volume1/Movies: machines that join this home later find the same share.

3. Make the compose file

Open the install page, choose UGREEN, and answer: the user, the memory, the data folder, your media folders, hardware video and the time zone. Copy the file. Nothing you type there leaves the page.

4. Create the project

Docker → Project → Create: name maktaba, keep its storage path inside the docker folder, paste the file, and Deploy. UGOS Pro downloads the image and starts it; until its setup, the container's log says how to run it.

5. Run the setup and choose the role

Over SSH, run:

sudo docker exec -it maktaba /opt/maktaba/server/bin/maktaba-server container setup

Answer its questions: a name for the admin account (not admin, which Maktaba keeps for itself), its password, and the folders with your videos. For each folder setup asks the name of the share your other computers open it by. The NAS needs the internet for this step: setup downloads the transcription and search tools (about 2 GB) and the speech models. Maktaba starts by itself when it finishes. Open http://<your NAS>:8088, sign in, and add a library for each folder: Manage → Manage libraries → Add library.

These steps make the NAS your Maktaba home. A computer with a graphics card can join it later (After setup). If your home runs on another computer instead, the NAS needs no Maktaba: share its folders and that home reads them (Home, machine or storage).

Ports

  • UGOS Pro's own pages are on 9999 (HTTP) and 9443 (HTTPS), clear of Maktaba's 8088, 8080, 8081 and 54329.
  • Another app on one of Maktaba's ports (a media server's, for one): Maktaba moves a taken web, API or live TV port to a free one from 8780 to 8790 by itself, and setup and Settings → This machine show the new one.
  • To choose a port yourself, remove the # in front of its line in the file's [ports] block, set a free port, and deploy the project again. A port you set is never moved: if another program holds it, Maktaba stops and its log names the port (A port is taken).

Hardware video

On an Intel model, choose Intel or AMD under Hardware video on the install page, and give it the render device's group: over SSH, run stat -c %g /dev/dri/renderD128. The file then passes /dev/dri and that group to the container (UGREEN's own guides do the same for other media servers), and Settings → This machine says Video: hardware. Without it, Maktaba converts in software.

Updates

Maktaba updates itself in its update window (Manage → Updates), and deploying the project again with a newer image is safe too: an older image never replaces a newer Maktaba. Each update takes a backup of the database first, so keep room for it on the data folder's volume. If a release cannot change the database, Maktaba goes back to the one you had by itself (An update did not go through).

Troubleshooting

  • The container stops at once: its log, in the Docker app, names the folder and the user. Give maktaba Read/Write on docker/maktaba (step 2) and start it again.
  • A library shows No access: give maktaba permission on that shared folder (step 2), then press Check access on the library's page.
  • Troubleshooting explains every other message; After setup covers quiet hours, speech to text, a reverse proxy and adding a computer with a GPU.
