Install Maktaba on ASUSTOR

Portainer runs Maktaba on ADM from one compose file.

All NAS guides · العربية

Not yet tested on an ASUSTOR device. ADM's menu names below come from ASUSTOR's own documentation, and the same file runs on every Docker host; tell us at GitHub what you find.

For ADM 4.2 and newer, with Portainer CE from App Central. About 20 minutes. Maktaba runs as a user you make for it, never as root.

Before you start

  • Memory: Maktaba needs 3.5 GB it may use. The Celeron N5105 models ship with 4 GB, which just fits on the Light tier; with more memory they reach Standard (which tier). A 1 GB ARM model, such as the AS1102T, serves best as storage.
  • An SSD for the data folder if there is one: the database and thumbnails are much faster there. Your media can stay on hard disks.
  • A GPU: the Intel Celeron models (AS5402T, AS6702T, FS6706T) have Quick Sync.
  • SSH: Services → Terminal → Enable SSH service → Apply. ADM lets only admin or root sign in over SSH.

1. Make a user and read its numbers

Access Control → Local Users → Add: name maktaba, a strong password, not an administrator. Then, over SSH as admin, run id maktaba: uid=1001 gid=100 is the answer 1001:100.

2. Give it its folders

  • Data: App Central's Docker apps keep their files in the shared folder Docker. Make the folder maktaba inside it, /volume1/Docker/maktaba, and give maktaba Read & Write on it.
  • Media: Access Control → Shared Folders → each folder with videos → Access Rights: Read & Write for maktaba where Maktaba may save subtitles and conversions, Read Only elsewhere. Deny Access wins over any other right.

Mount each folder in the container at its own path on the NAS, such as /volume1/Movies: machines that join this home later find the same share.

3. Make the compose file

Open the install page, choose ASUSTOR, and answer: the user, the memory, the data folder (/volume1/Docker/maktaba), your media folders, hardware video and the time zone. Copy the file. Nothing you type there leaves the page.

4. Deploy the stack in Portainer

App Central → install Portainer CE (it installs Docker Engine first when it is missing), and open it from ADM's menu; its first password is in Docker/PortainerCE/portainer_password.txt. Then Stacks → Add stack: name maktaba, Web editor, paste the file, and Deploy the stack. Until its setup, the container's log says how to run it.

5. Run the setup and choose the role

Over SSH as admin, run (with sudo in front if it is refused):

docker exec -it maktaba /opt/maktaba/server/bin/maktaba-server container setup

Answer its questions: a name for the admin account (not admin, which Maktaba keeps for itself), its password, and the folders with your videos. For each folder setup asks the name of the share your other computers open it by. The NAS needs the internet for this step: setup downloads the transcription and search tools (about 2 GB) and the speech models. Maktaba starts by itself when it finishes. Open http://<your NAS>:8088, sign in, and add a library for each folder: Manage → Manage libraries → Add library.

These steps make the NAS your Maktaba home. A computer with a graphics card can join it later (After setup). If your home runs on another computer instead, the NAS needs no Maktaba: share its folders and that home reads them (Home, machine or storage).

Ports

  • ADM's own pages are on 8000 and 8001, and Portainer CE on 19943, clear of Maktaba's 8088, 8080, 8081 and 54329.
  • Another app on one of Maktaba's ports: Maktaba moves a taken web, API or live TV port to a free one from 8780 to 8790 by itself, and setup and Settings → This machine show the new one.
  • To choose a port yourself, remove the # in front of its line in the file's [ports] block, set a free port, and update the stack. A port you set is never moved: if another program holds it, Maktaba stops and its log names the port (A port is taken).

Hardware video

On a Celeron model, choose Intel or AMD under Hardware video on the install page, and give it the render device's group: over SSH, run stat -c %g /dev/dri/renderD128. The file then passes /dev/dri and that group to the container, and Settings → This machine says Video: hardware. ASUSTOR's documentation does not cover /dev/dri in a stack; the device checklist confirms it. Without it, Maktaba converts in software.

Updates

Maktaba updates itself in its update window (Manage → Updates), and pulling a newer image in Portainer is safe too: an older image never replaces a newer Maktaba. Each update takes a backup of the database first, so keep room for it on the data folder's volume. If a release cannot change the database, Maktaba goes back to the one you had by itself (An update did not go through).

Troubleshooting

  • The container stops at once: its log, in Portainer, names the folder and the user. Give maktaba Read & Write on Docker/maktaba (step 2) and start it again.
  • A library shows No access: give maktaba Access Rights on that shared folder (step 2), then press Check access on the library's page.
  • SSH refuses the user: sign in as admin; ADM refuses other users over SSH.
  • Troubleshooting explains every other message; After setup covers quiet hours, speech to text, a reverse proxy and adding a computer with a GPU.
