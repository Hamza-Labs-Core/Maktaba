Install Maktaba on Unraid

One container from the Apps tab runs everything and updates itself.

All NAS guides · العربية

For Unraid 6.12 and newer with Community Applications (the Apps tab). About 15 minutes. Maktaba runs as Unraid's own nobody user (99, group users 100), never as root.

Before you start

  • Memory: 8 GB or more is comfortable; Maktaba runs from 4 GB.
  • A pool for the data folder: Maktaba's database must live on a cache pool or a single disk, such as /mnt/cache/appdata/maktaba, never on the array's /mnt/user share. Setup refuses the array for it, because its database would be slow and corruptible there. Your media stays on the array.
  • Hardware video (optional): with an Intel or AMD chip, check that /dev/dri exists (Tools → System Devices, or ls /dev/dri in the terminal). If it is missing, install the Intel GPU TOP plugin from Apps, which loads the driver.

1. Find Maktaba in Apps

Apps → search Maktaba → Install. Until Community Applications lists it: Docker → Add Container → Template repositories, add https://github.com/Hamza-Labs-Core/Maktaba and Save, then choose Maktaba under Template.

2. Fill in the template

  • Data: keep /mnt/cache/appdata/maktaba, or another pool's appdata folder.
  • Media: your share, for example /mnt/user/Media. Set Container Path to the same path as Host Path: machines that join this home later find the same share. Set Access Mode to Read Only where Maktaba must never write. Add another Path for each further share.
  • Time zone: yours, for example Asia/Riyadh.
  • Render device: keep /dev/dri for hardware video, and add the render group to Extra Parameters: --user 99:100 --stop-timeout 90 --group-add 18, where 18 is what stat -c %g /dev/dri/renderD128 prints on your server. Without a GPU, remove the device.
  • Network Type: keep Host. Your phones and TVs then find Maktaba by themselves.

Apply. Unraid downloads the image and starts the container.

3. Let Maktaba read your shares

Unraid's shares belong to nobody:users, so Maktaba can usually read them as they are. Files copied in another way (over SSH as root, by another container as another user) may not be readable: Tools → Docker Safe New Perms gives them back to nobody:users. A share Maktaba can't read shows No access in Maktaba, with this fix.

4. Run the setup

Docker → click Maktaba's icon → Console, and run:

/opt/maktaba/server/bin/maktaba-server container setup

Answer its questions (the admin's name and password, your libraries). Maktaba starts by itself when it finishes. Open WebUI from the icon's menu, or http://<your server>:8088.

After setup

  • When the array is stopped, the shares are gone for a while: libraries show No access, and nothing in them is treated as deleted. Start the array and press Check access.
  • Updates: Maktaba updates itself inside its update window (Admin → Updates). Unraid's "update ready" for the image is not needed; applying it does no harm.
  • After setup for quiet hours, speech to text, a reverse proxy and adding a computer with a GPU; Troubleshooting for each message.
